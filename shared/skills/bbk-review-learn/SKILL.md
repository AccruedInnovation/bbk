    # BBK Review Learning

1. Select exact runs, findings, dispositions, escaped defects, repairs, context failures, or evidence gaps.
2. State the proposed reusable lesson, applicability, supporting and contrary evidence, causal confidence, uncertainty, privacy/export class, and proposed action.
3. Compact duplicates without losing provenance or dissent.
4. Keep status `PROPOSED`. A learning candidate cannot modify method content, roles, profiles, rubrics, gates, assurance, or policy.
5. Adoption requires a separate steward decision, bounded experiment where appropriate, qualification, and successor release.
6. Do not generalize one project-specific workaround into universal ceremony.

## Profile-specific learning

Tag profile-derived learning with the exact profile and toolchain scope. Route a proposed reusable change to that profile's steward unless evidence supports a genuinely host- and language-neutral BBK method change.
