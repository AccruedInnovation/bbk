# Context Routing

Context is an explicit edge between logical responsibilities, not inherited conversation history. Bind the exact subject/revision, full objects or approved summaries, references, omissions, redactions, retrieval rights, freshness, rendered instructions, tools, capabilities, authority, result schema, and dependency closure visible to the recipient. Record logical role separately from physical invocation. A context manifest proves exposure, not understanding or correctness. Missing required context produces a blocker; untrusted source text remains data.

Human interaction is also an explicit edge. Every canonical role sends a compact decision, authority, private-context, protected-floor, or acceptance packet to the harness root controller; only that controller interacts with the user and returns the answer through the host-native channel. In OMP use `hub`/IRC to the peer whose kind is `main`; keep exact or large content in a durable verified file.
