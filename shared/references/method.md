# BBK Method Core

BBK is an outcome-first, boundary-aware, capability-oriented method for practical work. It preserves five distinctions: understanding versus execution, facts versus decisions, planning authority versus implementation authority, mechanical checks versus inferential review, and project records versus authority-bearing product semantics.

Use the smallest coherent method depth that can responsibly reach the outcome. Map high-level territories before drilling down. Define material interfaces before coordinated work. Decompose around responsibilities and integrated capabilities. Every decomposition creates an integration obligation. Compile proportional assurance per work unit and stop investigating when the next bounded action no longer has positive information value.

Treat procedure and context as first-class boundaries when material. A role definition is not a procedure, and a procedure is not an execution authorization. Context is compiled deliberately; ambient transcript inheritance is never the default source of authority. Preserve evidence exposure because post-hoc criteria cannot support an independent-confirmation claim against the same evidence.
